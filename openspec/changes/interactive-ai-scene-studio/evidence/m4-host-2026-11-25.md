# M4 hosted selection attach, 2026-11-25

Actual-host evidence for task 5.10 (partial). ChatGPT web, Work mode, on the personal EC2 pilot. The build, account and
connector identifiers are redacted. Times are UTC.

## Symptom

After the declutter release (`d84d44a9`), drawing an area in the embedded Studio showed "Chat couldn't attach the
selection. Select again to retry." The AI said it could not see the live selection.

## What the pilot saw

- `studio_chat_selections` had no rows at all, including clears. A failed attach also sends a small, valid clear, so
  every `studio_stage_chat_selection` call failed before the store.
- A filtered packet capture on the pilot's internal MCP and room-server ports, 07:40–07:41, showed four
  `studio_inspect_correction` calls and no stage call. The user reported no ChatGPT prompt.
- The PostgreSQL stage path passed `apps/server/test/studioPostgresRace.test.ts` (7 tests) on an isolated database.
  The table and the `20261124193000_studio_chat_selections` migration were present on the pilot.

## Root cause

A wrapped `fetch` in the chatgpt.com page recorded ChatGPT's tool proxy (`/backend-api/ps/mcp`). It answered the view's
`tools/call` for `studio_stage_chat_selection` itself:

```json
{"error":{"code":-32001,"message":"Unknown tool","data":{"name":"studio_stage_chat_selection"}}}
```

A `tools/list` through the same proxy returned the app's 23 Session Zero tools without `studio_stage_chat_selection` and
`studio_start_correction`, both added 2026-11-24. Its `studio_open` named view `ui://session-zero/studio.3a8d027eb0f52331.html`.
The current release was `ui://session-zero/studio.128e11fe78598ce9.html`. ChatGPT's snapshot of the tools predated
2026-11-24. The server deliberately serves the current view at any earlier view address, so the new view loaded while
the host lacked the tools it calls. New chats and new builds did not refresh the snapshot.

## Fix and result

Settings → Plugins → the app → Manage app → **Refresh tools**. The capture showed `tools/list` reach the MCP server at
08:38:10 with both tools. In the same chat:

1. Choosing **Select area** and dragging over a cave floor showed "Selection attached. Ask for the change in chat."
2. Asked to describe the selection without changing anything, the AI reported a 6-by-5-square area on the map, columns
   16–21 and rows 16–20, mostly floor with a debris pile whose squares were already blocked or difficult, and no walls,
   doors, windows, marks or creatures. It made no change.

This verifies an attached selection and a description before any request. It does not cover redrawing, clearing, a
second view or a started correction.

## Unproven change

Release `7249e8d1` also labels `studio_stage_chat_selection` read-only and logs attach failures to the view console. It
was deployed before the root cause was found, so whether the host needs the read-only label was not tested. The
product owner kept it ([D15](../design.md#d15-m4-correction-interaction)).
