## Security and fidelity coverage

- Disk and S3 originals/previews refuse unauthenticated/foreign/identifier-only requests,
  reserved `/uploads` and encoded paths, traversal, and the static fallback. Actual S3
  anonymous GET/HEAD/list is denied, with selectively public suffix policies as negative
  controls. A legacy public object remains readable. Private successes/errors are no-store.
- Downloads accept only the two approved concrete origins; tests cover credentials,
  redirects, timeout/size/truncation/compression, private IPv4/IPv6 and rebinding controls.
  No application credentials are forwarded; descriptor/host metadata is not persisted.
- Exact original hashes and raw/canonical dimensions are distinct from the preview.
  Eight EXIF orientations use quadrant pixel assertions, including reflection.
  Corrupt/oversized/expired files preserve earlier successes. Concurrent receipt/content
  retry and partial revocation/unknown outcomes do not silently duplicate originals.
- Reads recheck grant/pass/session after storage work. Review regressions cover sign-out
  during original/preview reads, selective public suffixes and mixed-case parser errors.
- Both stores cover derivative quota bytes, write-time access, late-put cancellation,
  expired intent refusal, failed deletion retry and abandoned-build age races. Existing
  published/legacy behavior is covered by the full server suite.
- Resource/open responses carry no private image or credential. App-only media renders as
  `data:`. Browser bridge tests cover attachments/picker/device controls, en/zh-TW, keyboard,
  reopening, foreign-owner clearing, visible-only polling and teardown.
